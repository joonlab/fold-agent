# 만든 과정 — 2026-09-26 ~ 09-28

원래 저장소에는 세션이 끝날 때마다 다음 세션에 넘기는 인계 문서가 14개 있었습니다. 실사용 요청 문장·실행 id·개인 맥락이 섞여 있어서 공개본에서는 빼고, 흐름만 이 문서로 줄였습니다. 모든 작업은 Claude Code 와 함께 했고, 원래 저장소의 커밋은 사흘 동안 200개(9/26 75 · 9/27 87 · 9/28 38)였습니다. 공개본은 그 히스토리를 가져오지 않고 새로 시작합니다.

## 1일차 (9/26) — MVP, 지식 베이스, 도구 공백 메우기

- **출발점**: 「폰 자체에서 Claude Code 같은 걸 돌릴 수 있나?」 접근성 서비스로 화면 트리를 읽고, 온디바이스 음성 인식으로 말을 받고, OpenAI 호환 LLM 에 도구 호출을 받아 탭·입력·스크롤을 실행하는 구조로 잡았습니다. LLM 은 집에 있는 맥의 프록시를 사설망으로 불렀고, 폰에서 function call 한 번 왕복이 약 2.2초였습니다.
- **MVP**: 「설정에서 배터리 잔량」이 5단계 15초에 맞게 나왔습니다. 처음부터 확인 게이트(실행/취소, 40초 무응답은 거부), 상태 오버레이, 정지 버튼을 넣었습니다.
- **첫 큰 실패**: 내비 앱에서 같은 버튼을 12번 연타하고 실패. 앱이 접근성 클릭을 「성공」으로 돌려주고 실제로는 무시하고 있었습니다. 그래서 「눌렀는데 화면이 안 바뀌면 좌표 탭으로 다시」와 반복 감시를 넣었고, 모든 실행을 기록(run trace)하도록 바꿨습니다.
- **폰 지식 베이스**: 설치된 앱 139개를 훑어 앱별 요령 58개, 딥링크 후보 105개 중 실기 통과 38개, 설정 바로가기 46개, 별칭 265개를 만들었습니다. 쇼핑 앱 검색이 6단계 38초에서 2단계 14초로, 내비 검색이 25단계 실패에서 2단계 13초로 줄었습니다.
- **경로 조건**: 「어디서 어디까지, 이 옵션으로」를 모델이 지어낸 좌표로 채우다가 실제 위치와 약 1km 어긋난 것을 보고 지오코더 도구로 바꿨습니다. 조건 체크리스트를 넣은 뒤 5개 조건을 5단계 30초에 모두 맞췄습니다.
- **확인 게이트 재설계**: 처음엔 화면에 「송금」 같은 글자만 보여도 확인을 물었습니다. 「실행 버튼을 누를 때만」 묻도록 바꾸고, 48종 대상으로 전후를 비교했습니다.
- **도구 공백 13개**를 우선순위로 정리해 먼저 보여 준 뒤 구현: 스크린샷, 손전등·미디어·음량·밝기·방해금지, 화면 잠금, 일정 작성·알람·카메라 바로 열기, 스와이프, 클립보드, 접힘 상태, `quick_toggle`, `stopwatch`, 영역 캡처(`capture`), 삼성 노트 쓰기(`write_note`). 와이파이·비행기 모드·데이터 끄기는 비서 연결이 끊기므로 일부러 넣지 않았습니다.
- **실행 210건 전수 대조**: 금융 앱 최근 거래 5건을 노트로 정리하는 과제가 34단계에서 6단계가 됐습니다. 끝에는 에이전트가 시험하느라 만든 노트 36개·캡처 42장을 스스로 휴지통으로 옮기게 했습니다(확인 창마다 캡처로 대상을 대조한 뒤 승인).

## 2일차 (9/27) — UI 새로 만들기, 재계획, 비서 도구, 스킬 게이트웨이

- **UI/UX**: 벤치마킹과 시안을 병렬로 만든 뒤 워크트리 4갈래(팝업·빛/패널·기록·화면)를 병렬로 구현하고, 리뷰는 구현과 분리된 에이전트가 봤습니다. 결과는 핀치 인으로 부르는 빠른 입력 팝업, 화면 가장자리의 붉은 빛(3.6초 주기로 숨쉬기, 터치 통과, 캡처 때 숨김), 채팅식 작업 기록(보관·휴지통 30일), 폴드 자세별 배치(커버 세로/가로·펼침·테이블톱), 펼친 화면 2칸 모두 읽기(디스플레이 설정 11단계 → 3단계).
- **「왜 너처럼 추론 못 해?」**: 헤맨 실행 25건을 원인별로 나눠 보니 「이미 본 화면을 또 봄」과 「막혀도 전략을 안 바꿈」이 대부분이었습니다. 그래서 막히면 한 번 물러나 「본 것 → 가설 → 다음 전략」을 새로 세우는 재계획(Replanner, 최대 2회), 본 화면 한 줄 기억(SeenScreens), 화면을 거치지 않는 설정 읽기·쓰기(`system_setting`, 쓰기는 허용 목록 3키 + 확인 게이트)를 넣었습니다. 「충전 중 화면 켜기」가 16단계 헤매다 취소되던 것이 1단계가 됐습니다. 자세한 분석은 `design/reasoning/`.
- **비서 도구 11개**: 일정·브리핑·메일·기억 조회와 게이트를 거치는 일정 생성/삭제·메일 발송/답장·기억 추가. 집 맥의 기존 에이전트는 메일 발송을 요청마다 막을 방법이 없어서 부르지 않고, 폰 전용 라우트(허용 목록 op + 폰 전용 토큰)를 새로 만들었습니다. 실기 10개 시나리오 통과.
- **스킬·MCP 게이트웨이**: 폰 모델이 스킬 문서를 찾아 읽고(`skill_search`·`skill_view`) 집 맥에서 argv 로 실행(`run`)하는 방식. 판정은 서버의 정책 파일이 하고, 확인 창에는 실행할 명령 원문이 뜹니다. 웹 검색(48초, 출처 카드), 그림 생성(46초), 격리 컨테이너 코드 실행(1~1000 소수 168개 + 그래프 7초), 유료 영상 요약(확인 창에 예상 비용 → 백그라운드 → 알림) 등 10과제 통과.
- **끝까지 스스로**: 맡긴 일이 끝나면 결과 원문을 정리해 요약하고(1,541자 → 46자), 화면이 필요 없는 다음 단계는 자동으로 이어 가게 했습니다.

## 3일차 (9/27 밤 ~ 9/28) — Claude Code 위임, 방법 고르기, 사람 개입

- **Claude Code 위임(`claude_task`)**: 집 맥에서 헤드리스로 띄운 Claude Code 가 도구를 쓸 때마다 권한 요청을 받아 판정하고, 부작용이 있으면 폰에 원문 확인 카드를 띄웁니다. 실측해 보니 전역 설정의 allow 규칙이 이 판정보다 먼저 통과시켜서, 위임 실행에만 모든 부작용 도구를 `ask` 로 뒤집는 설정 덮개를 씌웠습니다. 「메일 보내 줘」를 맡기면 모델은 초안만 만들고, 거부하면 우회하지 않았습니다.
- **폰 파일 → 홈 서버**: 공유 시트와 📎 로 올린 파일을 서버가 준 id 로만 작업에 넘깁니다(모델이 폰 경로를 지어내지 못하게).
- **방법 고르기(`choose_way`)**: 웹 검색만 하던 것을 「웹 검색 / 앱에서 직접 / 위임」 중 고르게 하는 카드로 바꿨습니다. 10초 안에 안 고르면 추천안으로 갑니다.
- **폰 도구 이식**: 알림 읽기, 문자 읽기(연락처 이름 매칭, 본문은 로그에 남기지 않음), 다운로드 폴더 저장, 실행 중 화면 켜짐 유지. 도구로 안 되면 앱 화면으로 한 번 더 시도(`fallback_challenge`).
- **사람 개입(HITL)**: 에이전트가 헤맬 때 「✋ 내가 할게」로 넘겨받아 몇 번 탭하거나 말로 알려 주고 「▶ 이어서」를 누르면, 에이전트가 처음부터가 아니라 넘겨받은 화면에서 이어 갑니다. 모델 답을 기다리는 중이면 4~5ms 안에, 도구 실행 중이면 그 동작만 마치고(0.8초) 넘어옵니다. 진행 패널은 끌어 옮길 수 있고 탭하면 그 대화방이 열립니다.

## 교훈

1. **「성공」 응답을 믿지 말 것.** 접근성 클릭은 성공이라 하고 무시되는 일이 흔했습니다. 성공 판정은 화면이 실제로 바뀌었는지로 합니다.
2. **도구가 없으면 모델은 화면에서 헤맨다.** 스크린샷 도구 하나가 없어서 14단계를 헤매던 일이 도구를 넣자 4단계가 됐습니다. 헤맨 기록을 모아 도구 공백 목록을 만드는 것이 가장 효과가 컸습니다.
3. **게이트는 서버·코드가 결정적으로.** 모델에게 「조심해」라고 쓰는 대신, 도구 종류로 무조건 확인을 걸고 판정은 정책 파일로 했습니다. 기본 설정을 그대로 쓰면 게이트가 뚫린다는 것도 실측으로 잡았습니다.
4. **라이브 폴더에서 빌드하지 말 것.** 집 맥의 웹 앱을 운영 폴더에서 빌드하다 실패해 약 3분 중단된 일이 있었고, 그 뒤로 별도 폴더에서 빌드해 교체하는 절차로 바꿨습니다.
