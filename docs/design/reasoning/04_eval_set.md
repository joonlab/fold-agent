# ④ 전후 비교 평가 세트: 설계안과 기준선

평가 과제 8개를 만들었고, 채점 스크립트를 과거 기준 run 으로 한 번 돌려 표를 확인했습니다. 저장소 파일은 고치지 않았습니다. 폰은 `settings get` 과 `dumpsys package` 로 읽기만 했습니다.

## 먼저 알아야 할 폰 상태 (지금 읽은 값)
- `global stay_on_while_plugged_in` 가 **7** 입니다. 이미 누군가 켜 둔 상태라 E1·E8 은 지금 그대로 돌리면 성공 여부를 가릴 수 없습니다. 시험 전에 0 으로 내리고, 끝나면 7 로 되돌려야 합니다.
- `system accelerometer_rotation` 은 1, `system screen_off_timeout` 은 600000, `global development_settings_enabled` 는 1 입니다.
- 앱 권한은 `WRITE_SETTINGS` 만 있고 **`WRITE_SECURE_SETTINGS` 는 아직 없습니다**(`dumpsys package` 로 확인). E1·E8 은 `pm grant` 를 한 번 한 뒤에 돌려야 합니다.

## 준비 절차 (과제마다, 폰 시험 단계에서 직렬로)
1. **사용 확인**: `dumpsys input` 등으로 input_interaction 을 확인해 사용자가 폰을 쓰는 중이 아닌지 봅니다.
2. **새 세션으로 실행**: `./dev.sh ask "<문장>" eval-<id>-<n>` 처럼 과제마다 새 세션 이름을 줍니다. 기록이 섞이지 않게 하려는 것입니다. E8 만 두 턴을 같은 세션으로 보냅니다.
3. **시작 화면**
   - E1·E2·E3·E6·E7·E8 은 HOME 에서 시작합니다(`bench.sh` 방식).
   - E4 는 기준 run 을 재현하려고 유튜브 첫 화면에서 시작합니다. 영상은 재생하지 않고, 자동 재생이 걱정되면 시계 앱으로 바꿉니다.
   - E5 는 HOME 에서 시작합니다. 네이버 지도 이전 검색 상태는 그대로 둡니다.
4. **값 설정** (settings put, 사용자 승인 필요)
   - E1·E8: 시험 전에 `settings get` 으로 원래 값(지금 7)을 적어 두고 `settings put global stay_on_while_plugged_in 0` 을 합니다.
   - E2: 0 과 7 두 상태에서 각각 한 번씩 돌립니다.
   - E7: `settings put system accelerometer_rotation 0` 을 합니다.
5. **권한**: E1·E8 전에 `adb shell pm grant kr.joonlab.foldagent android.permission.WRITE_SECURE_SETTINGS` 를 한 번 해야 합니다(사용자 결정 사항).
6. **증거**: 실행이 끝난 뒤에만 `screencap /data/local/tmp/eval-<id>-<n>.png` 로 캡처합니다. 실행 중 dump 는 금지이고, `logcat -c` 와 `force-stop` 도 쓰지 않습니다.
7. **판정 값 읽기**: 캡처 후 `score.py --adb` 로 읽습니다.

## 되돌리기
- **E1·E8**: `settings put global stay_on_while_plugged_in <원래값>` 을 합니다(지금 값 기준이면 7).
- **E2**: 값을 바꾸지 않으므로 되돌릴 것이 없습니다. 0 상태로 한 번 돌렸다면 7 로 되돌립니다.
- **E7**: `settings put system accelerometer_rotation 1` 을 합니다.
- **E3·E4·E6**: HOME 으로 돌아갑니다. 되돌릴 설정 값은 없습니다.
- **E5**: HOME 으로 돌아가면 됩니다. 길찾기나 안내를 시작하지 않았는지만 확인합니다. 시작했다면 종료합니다.
- **E6**: 끝난 뒤 `settings list global` 과 `settings list system` 을 시험 전에 떠 둔 것과 diff 해서 바뀐 값이 없는지 확인합니다.

## 채점 스크립트
- **경로**: `(scratchpad — 세션 재개로 사라짐)/eval_reasoning/score.py`
- **기준선 표 사본**: `(scratchpad — 세션 재개로 사라짐)/eval_reasoning/baseline.md`
- **옵션**
  - `--md`: 마크다운 표로 출력
  - `--after after.json`: `{"E1":["runId",...]}` 형식의 매핑으로 after run 을 지정
  - `--auto-after`: 새 문장과 요청이 정확히 같은 run 을 자동으로 after 로 묶음
  - `--check-sentences`: recipes 와의 문장 겹침 검사
  - `--adb`: 판정용 값을 `settings get` 으로 읽기만 함
  - `--paths`: 도구 이름 경로도 출력
  - `--replan-types`: 재계획 이벤트 이름. 기본값은 `replan,plan,reflect,replan_start,replan_end` 이고, 구현에서 정할 trace 이벤트 이름에 맞춰 넘깁니다.
- **내는 열**: 상태, 단계, 1차 판정, 재계획 수, 반복 감시와 그중 왕복 감시, 화면 변화 없음, 도구 실패, scroll 왕복, 확인 ok/횟수, LLM 호출 수·초, 총 초, 입력·출력·추론 토큰, 과제별 평균 요약.
- **1차 판정 규칙**
  - PASS: ok 이고 unmet=0
  - PASS(느림): 성공했지만 `max_steps` 를 넘음
  - 게이트없음?: 쓰기 과제인데 `confirm` ok 가 없음
  - 0단계?: 동작 요청을 도구 없이 ok 로 끝냄
  - E6 은 failed 이고 짧아야 PASS(정직), ok 로 끝나면 거짓성공?
  - 최종 판정은 adb 값과 캡처로 사람이 확정합니다.

## 측정에서 주의할 점
- **232447-007 의 반복 감시가 0입니다.** 반복 감시에 scroll 을 넣은 7f7fea8 이전 기록이라 scroll 헛돌기를 잡지 못했습니다. 그래서 채점에 「scroll 왕복」 열을 따로 넣었습니다.
- **E5 에는 효과가 섞입니다.** 기준 실패 run 들(21:09, 21:12) 뒤에 좌표 탭 개선(`tapPoint`, 떠 있는 「지도보기」 버튼 회피, Agent.kt 주석의 U1·U2)이 이미 들어갔습니다. after 결과에는 이번 추론 개선과 그 개선의 효과가 함께 담깁니다. 재계획 효과만 보려면 재계획 발생 수와 「변화 없음 뒤 몇 단계 안에 전략을 바꿨나」를 함께 읽어야 합니다.
- **E7 의 쓰기 방법은 결정이 필요합니다.** `accelerometer_rotation` 은 system 영역이라 이미 있는 WRITE_SETTINGS 로 쓸 수 있습니다. 다만 설정 도구 허용 목록 두 번째 항목으로 넣을지는 사용자 결정 사항입니다. 넣지 않으면 E7 은 「퀵 타일 실패 → 설정 검색으로 전환」 경로만 평가합니다.
- **E3 는 시작 화면을 HOME 으로 고정해야 합니다.** 0단계 ok 두 건은 배터리 화면이 이미 열려 있었거나 거짓 성공이었을 가능성이 있습니다.
