## 4. 추천

1. **재계획 트리거는 조합 C′로 정합니다.**
   - 발동 조건: `oscillation/same guard 경고` 또는 `무진척 ≥4` 또는 `화면 변화 없음 ≥3연속`(도구 종류 무관) 또는 `도구 실패 ≥2연속` 또는 `같은 화면이 최근 10단계 중 4회`
   - 무진척 = 화면을 조작하는 도구가 연속으로 새 화면을 못 만든 횟수입니다.
   - 진척 인정: 새 화면 해시, 또는 note·capture·write_note 성공 시 카운터를 초기화합니다.
   - 쿨다운 4단계, 한 실행에 재계획 최대 2회. 3번째 발동이면 사용자에게 묻거나 정직하게 finish합니다.
   - 실측으로는 탐지가 10→19/25, 지연은 6→3단계로 줄고, 깨끗한 ok 188건 오탐은 0입니다.
   - 발동은 전체 272실행 합쳐 88단계이고, 쿨다운을 적용하면 재계획 호출은 약 35~40회입니다. 큰 모델 호출 비용은 이 정도로 한정됩니다.
   - 「새 화면 없음 3연속」과 「화면 변화 없음 2연속」은 오탐이 커서 쓰지 않습니다(구간 밖 12~15회).
   - 고정 점검(12단계)은 탐지를 1건 늘리는 대신 20실행에서 오탐이 나서 쓰지 않습니다. 대신 **단계 한도의 60%(15/25)에서 한 번 진척을 점검**하는 방식을 권합니다. 신호로 못 잡는 탐색형 헤맴(153234, 191543)이 이 점검에 걸립니다.

2. **② 화면 기억의 형식**을 `앱·화면제목 | 화면 해시 앞 4자 | 본 것/없는 것 한 줄`로 제안합니다.
   - 예: `설정/개발자 옵션 p1·p2 — 「충전 중 켜짐」 없음`
   - 금융·지도 사례처럼 look 결과(「카드 없음」)나 이미 기록한 상세 항목도 함께 남겨야 합니다. 기억이 부원인인 8건 중 6건이 이 경우입니다.
   - 재방문하면 도구 결과에 「이 화면은 N단계에 봤음: 요약」을 붙이는 것만으로도 금융앱 3건의 왕복을 끊을 수 있다고 봅니다.

3. **재계획 프롬프트 입력**: 지금까지의 화면 기억 요약, 최근 6단계의 (도구·결과·새 화면 여부), 발동 사유를 넣습니다. 출력은 `가설 2~3개 + 다음 전략 1개`이고, 전략 종류는 다른 경로·다른 도구·포기하고 안내 중에서 고르게 합니다. 사례에서 나온 전략 전환 예:
   - 노트 입력 실패 → write_note
   - 스크린샷 → capture
   - 설정 항목 없음 → 설정 검색 또는 설정 도구

4. **③ 설정 도구 허용 목록 후보** (실측 근거):
